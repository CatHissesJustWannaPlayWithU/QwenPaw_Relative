# 候选复核、正式入证与学习：产品和维护约定

本文面向徐州招商工作台的业务使用者与维护开发者。它说明“候选”“待补证”“观察”与“正式证据”之间的边界，避免把一个界面状态误解成事实确认、招商推进或自动外联。

## 业务人员的最短路径

1. 在“候选与关系”页先分清两张互斥的表：
   - **已发现公开网页链接，尚未形成服务器留存材料**：服务器只保存了链接、标题和搜索摘要；还没有保存该网页的原始页面副本、可见文本、服务器采集时间和内容哈希。它不是要求业务人员再找一个文件；浏览器打开原网页也不会写入台账。这里不能“查看材料”或“入证”；通常等待固定计划在合规范围内保存页面，或先作业务判断。
   - **已保存页面材料，等待人工判断**：服务器已保存并校验一份公开页面快照（可见文本、原始字节哈希、采集时间和来源 URL）。这才是唯一的“查看材料”入口；同一条记录不会再同时出现在上一张表。
2. 点击“查看材料”。页面展示的是服务器已保存的公开页面快照；它不是正式企业事实。
3. 阅读摘要、来源和需要核对的全文后，选择一种处理方式：
   - **待补证**：候选有价值，但暂时缺少中国业务、徐州关联、投资落地或其他关键公开依据。系统保留它为待办；业务人员要写明缺什么。
   - **观察**：暂不值得立即投入核验时间，但不应删除。系统仍可在固定低频自动观察池内访问公开页面；不会因此确认事实、创建线索或联系企业。
   - **无效**：与招商范围明显无关或不适用。系统停止此候选的后续自动访问，但历史材料和判断理由保留。
4. “关联证据草稿”显示“等待人工确认”不等于一定能入证。只有下列前提都通过，页面才显示“请求重新核验并入证”：实体名称、实体类型、来源发布日期、事实类别和原始摘录完整，且候选不缺中国业务、徐州关联或投资落地的公开依据。任一前提不满足时，页面会写出缺项，并明确“服务器尚未访问原页面”；业务人员不能在浏览器补写这些事实字段。
5. 服务器返回“已生效”时，服务器核验材料已经追加，可从“线索与证据”查看；返回“暂未生效”时，系统会显示是否根本未开始抓取或抓取后未通过，以及准确原因，且不会新增服务器材料或线索。业务人员若能合法打开同一页面，可改走“人工材料入账”，但该材料会始终标记为人工提交。

## 一次重新核验到底做了什么

以“已保存页面材料”中的一条草稿为例，业务人员点击 **请求服务器重新核验** 后，系统不会把点击本身当作通过，而是按以下顺序执行：

1. 读取不可编辑的草稿：拟定主体、主体类型、页面日期、事实类别和原始摘录均来自已经保存的页面快照；用户只能提交“自己核对了什么”的备注。
2. 检查能否开始：草稿字段和地域前提不完整时，系统记录具体阻断项，**不会访问原网页**。
3. 重新访问同一个台账 URL：依次检查 robots、访问退避和公开页面访问是否允许。
4. 核对当前网页：草稿主体、页面日期和原始摘录必须仍能在当前网页中找到。网页更新、网页删改、自动草稿日期误取或摘录变化，都会导致本次核验停止。
5. 只有全部通过：服务器才签名追加服务器核验材料；否则只追加“谁在何时请求过、服务器在哪一步失败、具体原因和建议下一步”的审计，不生成服务器材料或线索。

例如“服务器已重新抓取，但找不到草稿页面日期”表示服务器**确实访问了页面**，但拒绝把抓取当天替代网页日期。业务人员不应在浏览器手填一个日期来绕过校验；应选择待补证、观察或无效，或仅在原网页已有新的明确公开内容后再次请求核验。

## 地域与业务价值：两条独立的人工判断

“徐州字段”不再和“中国业务”混成一个不可解释的开关。工作台会分别显示：

- **地域优先级**：标题/摘要已明确徐州的材料进入“有徐州字段（高优先）”；没有明确徐州字段的材料显示为“无徐州字段（地域低优先）”。这只决定优先看哪一条，不等于企业价值、投资意愿或事实确认。
- **业务价值**：仍由业务人员基于保存材料决定。没有徐州字段的材料不会被删除或自动降为无效；团队可以把它视为高价值材料继续研判。
- **企业来源地**：只有业务人员明确选择“无需徐州字段”时才填写，例如“北京｜总部所在地”。它必须附“在保存材料中如何确认中国业务”的文字依据，绝不能根据投资界、新闻媒体或网站域名推断企业所在地。

### “无需徐州字段”如何生效

1. 在已保存材料的抽屉中阅读页面；如果该记录是旧版合并地域门槛，会显示“地域判断：尚待人工决定”。
2. 点击 **无需徐州字段**，填写企业来源地、其性质（注册地/总部/经营地）、中国业务人工核验依据及业务判断理由。
3. 系统只追加一条带登录用户和服务器时间的地域判断审计。此时页面不会被抓取，也不会产生正式证据。
4. 回到该草稿，点击 **请求重新核验并入证**。服务器会再次读取该审计；只有中国业务人工确认、来源地和理由都存在时，才继续按原有 robots、来源退避、正文实体/日期/摘录一致性和证据完整性校验访问原页面。
5. 任一服务器校验失败，仍然不会新增正式证据。成功后，证据链与“无需徐州字段”审计会同时保留，供后续追溯谁作了范围判断、何时由服务器核验入证。

旧数据不会被系统自动豁免：历史上只有“缺中国/徐州依据”的合并标记时，一律显示为“地域依据待人工决定”。

谁负责什么：已登录且在团队名册内的业务成员作判断和提交复核依据；服务器在确认时重新抓取、核验并记录审计；固定来源监控按既定计划低频观察公开页面。系统不会自动联系企业、承诺政策或推进招商。

## 状态与真实效果

| 用户选择或结果 | 写入位置 | 自动访问效果 | 是否新增正式证据 |
| --- | --- | --- | --- |
| 待补证 (`need_evidence`) | 候选/草稿业务判断审计 | 仍可进入固定低频观察 | 否 |
| 观察 (`observe`) | 候选/草稿业务判断审计 | 仍可进入固定低频观察 | 否 |
| 无需徐州字段 (`waive_xuzhou`) | 候选业务判断审计，含企业来源地和中国业务人工核验依据 | 仅让后续“服务器重新核验”可尝试；不直接联网 | 否 |
| 无效 (`invalid`) | 候选/草稿业务判断审计 | 停止该候选后续自动访问 | 否 |
| 等待人工确认 (`pending_human_confirmation`) | 服务器生成的证据草稿 | 不等于已入证 | 否 |
| 已重新核验入证 (`confirmed_and_captured` / `confirmed_with_existing_evidence`) | 确认审计和正式证据链 | 与候选判断分开 | 是 |
| 重新核验未通过 | 确认审计 | 不改变历史候选 | 否 |
| 预检查未通过（字段缺失或中国/徐州范围缺口） | 确认审计 | **服务器不访问原页面** | 否 |

“待补证”和“观察”的差异主要是业务优先级与团队下一步；目前两者都不会向某位人员自动派工，也不会承诺针对单条候选自动找到补充材料。只有无效会退出后续自动观察预算。

## 人工材料与自学习的真实边界

当你本人可以合法阅读页面、但服务器不能访问时，不需要反复等待机器重试。可在业务页
“人工材料入账”登记关键原文、正常来源链接、访问方式和有权使用声明；可选上传关键截图、
PDF 或文本导出。服务器只保存提交人、时间、哈希和材料包，不会读取你的 Cookie、密码或
浏览器会话，也不会把人工材料冒充成服务器抓取。

人工材料可进入后续人工招商审批，但不能进入机器自动评分、风险词判断或事实分类。待人工
跟进有真实结果后，可记录“推进、落地、暂缓、未转化或无效”；该反馈只改善同类来源的阅读
优先级，不能改写原始材料或替人决定招商结论。

## 自学习的真实边界

一次服务器核验材料或人工材料的真实结果会成为来源有效性统计样本，但不会立即或自动改写
系统。每日结果学习周期读取过去 90 天的数据；来源样本少于 **3 条** 时仅供参考。默认模式
最多自动调整业务队列的阅读顺序；只有团队成员在“来源与学习”明确选择更高自动化模式后，
机器才可能重排现有固定来源配方。

自动化也只能创建新的固定来源配方排序版本。系统不会自行新增来源、修改 Skill、搜索词、
URL、产业范围、历史材料、线索、评分或既有人工判断。团队成员随时可以改回“只给建议”，
登记/停用可信域名，或用人工材料补齐服务器无法读取但其有权使用的页面。

## 开发维护约定

### 前端层级

- 任何由候选材料抽屉发起的任务，必须先执行 `setObservationDrawerOpen(false)`，再设置 `task`；`TaskReviewModal` 的 `zIndex` 固定高于 Drawer。禁止同时保留可交互 Drawer 和 Modal，防止 Modal 被遮挡。
- 长快照或摘要必须使用 `CollapsibleText`，且按钮文本必须成对提供“展开全文 / 收起”。不要使用只能展开的 Ant Design `Paragraph.ellipsis`。
- 候选表格使用固定布局与固定“下一步”列；业务操作不得只依赖长标题链接或被横向滚动遮挡。

### 接口与回执

- 候选业务判断只允许 `POST /discovery-candidates/{candidate_id}/business-review`。常规请求体仅含 `decision` 和 `review_note`；`decision=waive_xuzhou` 时必须附 `enterprise_origin`（来源地、性质、中国业务人工核验依据和确认标记），其余决定不得夹带该对象。
- 草稿确认只允许 `POST /evidence-drafts/{draft_id}/confirm`，请求体仅可含 `review_note`。后端先进行不联网预检查：草稿字段完整性与候选中国/徐州范围门槛；任一项失败时返回 `preflight.capture_started=false`、只追加失败审计，不调用抓取器。前端必须据此显示“服务器未访问原页面”和实际阻断项，不能仅显示“请求已完成”。
- 写入成功后必须调用 `refresh()`，并将正式入证结果提供到“线索与证据”页的跳转入口。

### 重新核验的底层顺序

1. 浏览器只提交草稿 ID 和复核备注；登录用户身份由认证中间件取得，浏览器不能提交或覆盖实体、URL、日期、摘录、哈希或操作者。
2. 服务端读取已签名台账中的草稿与候选，检查草稿的五个必需字段和地域范围。旧合并门槛默认失败；仅当已有“无需徐州字段”审计、企业来源地和中国业务人工核验依据时，才把徐州字段视为本条材料的非必需项。失败即追加 `confirmation_rejected_incomplete_draft` 审计，`capture_attempted=false`，不联网。
3. 预检查通过后，服务端才按台账保存的候选 URL 访问原页面，并依次遵守 robots、来源退避和允许来源约束。
4. 服务端校验当前正文中仍能找到草稿实体、原始摘录和来源日期，校验原始字节哈希、来源级别及正式证据字段；任一步失败都不新增证据或线索，只记录失败审计。
5. 只有全部校验通过，才在正式 `evidence` 链尾部追加一条新证据并生成确认审计。确认流程禁止修改旧证据、草稿、观察快照、评分或历史业务判断。

### 回归检查

1. 在材料抽屉内点击“选择处理方式”和“请求重新核验并入证”，确认任务模态框位于最上层且抽屉已关闭。
2. 确认短文本有“展开全文”，展开后有“收起”。
3. 确认已有观察快照的候选只出现在“已保存页面材料”表；“仅有链接、尚未形成服务器留存材料”表不能显示“查看材料”，且必须明确显示缺少的是页面副本、可见文本、采集时间和内容哈希。
4. 确认草稿缺字段或候选缺中国/徐州依据时不显示入证按钮，并显示“服务器尚未访问原页面”；完整且范围通过的 `pending_human_confirmation` 草稿才可见按钮；`invalid` 草稿不可再次确认。
5. 对确认接口模拟成功、联网校验失败和预检查失败响应，确认页面分别显示“已生效”“未新增正式证据”“服务器未访问原页面”；联网校验失败必须显示具体失败阶段、原因和业务人员下一步，并在成功时能切换到“线索与证据”。
6. 运行插件单元测试与前端 `npm run typecheck && npm run build`。
