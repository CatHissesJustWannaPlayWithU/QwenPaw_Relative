# 小红书热点简报

这个 Skill 面向普通用户，把“给我生成一份简报”“我最近更关注 AI 和旅行”“把简报发到邮箱”等自然语言请求，转换为小红书热点采集、保存、报告生成和邮件发送流程。

## 核心原则

1. 用户只需要表达目标，不要求用户记住工具名称、参数名称、兴趣权重、SMTP 或服务器文件路径。
2. 底层工具负责具体动作：采集、保存快照、保存偏好、生成文件、列出历史记录和发送邮件。本 Skill 只负责理解意图并安排调用顺序。
3. 默认只使用免费来源。调用采集工具时必须使用 `allow_paid_source=false`，不得在免费来源失败后静默切换到付费接口。
4. 只能报告真实返回的数据。采集失败时说明真实错误，并明确表示本次没有生成新的热点数据；不得编造热点、来源、热度、快照或邮件结果。
5. 简报中尽量保留 `capture_id`、采集时间、来源名称、来源链接、数据条数和警告信息，保证结果可以追溯。

## 请求识别与调用顺序

### 1. 用户要求“给我生成一份简报”

先检查当前智能体工作区中是否有可用的小红书热点快照。

- 如果没有可用快照，或者用户明确要求最新数据，调用 `collect_xhs_hotspots`，参数使用：`limit=10`、`force_refresh=true`、`allow_paid_source=false`。
- 采集成功后调用 `create_xhs_briefing(lookback_days=7)`。
- 如果采集失败，停止后续生成，返回真实错误和排查建议，不要用模型知识补写热点。
- 如果已有可用快照，优先使用已保存数据生成简报，并在结果中说明数据的采集时间。

普通用户的回复重点应是简报内容、数据来源、采集时间和可下载文件，不必主动暴露内部工具名。

### 2. 用户要求“采集小红书热点”或“给我热搜前十”

调用 `collect_xhs_hotspots(limit=10, force_refresh=true, allow_paid_source=false)`。

返回时说明：采集是否成功、实际来源、采集时间、前十条内容、快照标识和保存结果。若免费来源不可用，原样报告错误，不能改用付费来源或虚构内容。

### 3. 用户表达兴趣偏好并要求简报

例如：“我最近更关注 AI、旅行和美食，娱乐内容少一点。给我生成一份简报。”

- 从用户刚刚明确表达的内容中提取简短偏好摘要。
- 调用 `create_xhs_briefing(preference_hint=<用户明确表达的偏好>, lookback_days=7)`。
- 不要求用户填写数字权重，也不向用户展示内部权重计算结果。
- 只在用户明确表达偏好后保存或使用偏好；不得从无关对话中猜测兴趣。
- 结果中只说明“已按 AI、旅行、美食等偏好排序”，不展示原始记忆、完整聊天记录或内部关键词。

### 4. 用户要求“生成个性化报告”

如果已经存在明确确认的偏好，调用 `generate_xhs_personalized_report(lookback_days=7)`；如果没有已保存偏好，优先调用 `create_xhs_briefing(lookback_days=7)`，让系统使用通用简报模式，不要擅自编造用户兴趣。

生成结果应包含报告标识、数据来源、覆盖时间范围和报告文件信息。若没有有效快照，先按“请求识别与调用顺序”第 1 条采集。

### 5. 用户要求查看历史快照或最近采集记录

调用 `list_xhs_hotspot_snapshots(limit=<用户要求的数量，默认 5>)`。

这个操作只读取工作区中已经保存的数据，不重新采集。返回快照标识、采集时间、来源、条数和文件位置；如果记录不足，明确说明当前只有多少条。

### 6. 用户要求查看已生成的简报

调用 `list_xhs_personalized_reports(limit=10)`，返回已生成报告的标识、生成时间、覆盖范围和文件名称。不要把本地绝对路径作为普通用户必须理解的内容，除非用户明确要求路径。

### 7. 用户明确要求把简报发送到邮箱

邮件发送必须由用户明确提出，不能因为生成了报告就自动发送。

- 用户没有指定报告时，优先使用当前刚生成的报告；如果没有当前报告，调用 `list_xhs_personalized_reports` 让用户确认，或先生成一份简报。
- 调用 `send_xhs_personalized_report_email(report_id=<报告标识>, recipient_email=<用户明确提供的邮箱>)`。
- 不在聊天中索要 SMTP 密码、授权码或其他密钥；邮件服务凭据由管理员预先以加密凭据引用配置。
- 返回发送结果、脱敏后的收件人、发送时间、报告标识和回执信息。只有工具明确返回成功时，才能说邮件已发送。
- 如果邮件配置缺失或发送失败，说明真实错误；不要把“生成了报告”误说成“邮件已发送”。

### 8. 用户要求每天采集或定时采集

调用 `build_xhs_daily_collection_job` 生成定时任务 JSON。

这个工具只负责生成任务配置，不代表任务已经启用。默认先保持关闭，等待人工检查任务内容、来源、时间和服务器环境后再启用，避免在未验证时持续请求外部接口。

## 数据真实性与异常处理

- 采集结果必须来自工具实际返回的免费来源，并保留来源链接和采集时间。
- 若返回数据为空、字段不完整、来源不可访问或校验失败，应标记警告并如实说明。
- 如果快照来自缓存，应明确告诉用户这是已保存的历史数据，而不是刚刚重新采集的数据。
- 任何工具返回 `ok=false`、异常信息或策略拒绝时，都停止依赖该结果生成事实性热点内容。

## 回复格式

普通用户最终看到的回复应简洁但可核验，至少包括：

1. 本次完成了什么。
2. 热点数据的采集时间和来源。
3. 前十条或报告中的重点内容。
4. 可下载的 Excel、Markdown 或其他报告文件名称。
5. 若发送邮件，说明脱敏收件人、发送时间和报告标识。
6. 若有失败或警告，放在结果中明确说明。

不要声称“后台已经调用工具”却不给出工具的真实结果；也不要把内部文件路径、兴趣权重、SMTP 配置细节和完整记忆原文作为普通用户的必要操作步骤。
